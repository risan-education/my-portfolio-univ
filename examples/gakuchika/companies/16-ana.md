# ANAを想定したガクチカ例

想定職種: **グローバルスタッフ職**

基本例: [鉄道・交通インフラ](../08-infrastructure.md)

## この会社・職種で意識したい経験

この職種を想定するなら、**時間制約のある仕事を分解する → 役割と合図を決める → リハーサルで測る → 本番の遅れを次の工程で立て直す**経験が話しやすいです。

## 修正前のガクチカ

> 合唱団の定期演奏会で、舞台係として演目間の転換を進行表どおりに回すことに力を入れました。リハーサルで転換が予定より長くかかり後の演目が押したため、時間を計ると、転換ごとに動く人数と順番が決まっておらず、口頭の申し送りで動きが重なっていました。私は転換を運ぶ、置く、確認するの三つに分け、六人の持ち場と合図の記号を書いた手順表を作り、リーダーと出演者側の責任者に確認して順番を一部入れ替えました。二回目のリハーサルでは進行表の時間内に収まりました。本番では一つの演目で幕の合図が遅れ、開始が少し押しましたが、次の転換で合図の担当を一人に固定して立て直し、以後は進行表どおりに終えました。遅れた原因と手順表を次年度の舞台係に渡しました。手順を分けて分担すると人が入れ替わっても回ること、遅れたときは原因を一つに絞って次で直すことを学びました。

## 何を改善したか

修正前でも段取り改善は伝わりますが、作業内容が多く本人の判断が埋もれていました。改善版では、遅れの原因を「人数と順番が決まらず作業が重なること」と捉え、作業を3つに分解した判断を中心にしました。本番で別の遅れが出た際も、合図の重複に原因を絞り、次の転換から担当を1人に固定した流れを明確にしています。

## 改善版ガクチカ

> 合唱団の定期演奏会で、舞台転換の遅れを改善しました。リハーサルで予定時間を超えたため動きを計測すると、転換ごとの人数と順番が決まらず、口頭連絡で作業が重なっていました。そこで作業を「運ぶ・置く・確認する」に分け、6人の持ち場と合図を手順表にしました。2回目のリハーサルでは予定時間内に収まりました。本番では幕の合図が遅れて開始が押しましたが、原因を合図の重複と判断し、次の転換から担当を1人に固定しました。その後は進行表どおりに終えました。予定を守るには個人が急ぐより、作業と責任を分け、遅れが出たら原因を絞って次の工程で直すことが重要だと学びました。

## この例の強いところ

時間を守るために全員が急いだ話ではなく、作業と責任を分けています。リハーサルで一度改善しても、本番で新しい問題が出た際に原因を絞り、次の工程から修正しています。

## これから経験を作るなら：課題設定10例

| 課題 | おすすめする理由 |
| --- | --- |
| 舞台転換を改善する | 時間制約の中で作業分解と連携を経験できる |
| イベント進行を改善する | 複数担当の動きを一つの時間軸で考えられる |
| 受付時間を短縮する | 利用者を待たせる工程を観察できる |
| 旅行行程を管理する | 時間・移動・参加者の制約を扱える |
| 大会運営を改善する | 定刻進行と例外対応を経験できる |
| 機材搬入を改善する | 順序と役割分担の効果を測れる |
| 遅延原因を記録する | 感覚ではなく工程ごとに問題を探せる |
| 交代勤務表を改善する | サービスを止めない人員配置を考えられる |
| 連絡手順を改善する | 情報の重複や抜けを減らせる |
| リハーサル方法を改善する | 本番前に失敗を発見して修正できる |

## 進め方

作業を小さな工程に分け、各工程の所要時間と担当を記録します。遅れた場合は「もっと急ぐ」ではなく、待ち・重複・確認不足のどこで時間が増えたかを探します。本番で別の問題が起きた場合、その場で何を見て原因を絞ったかも残します。
