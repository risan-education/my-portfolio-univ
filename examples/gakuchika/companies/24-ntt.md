# NTTを想定したガクチカ例

想定職種: **研究開発職**

基本例: [IT・情報通信](../01-it.md)

※架空の学生の例です。本人の実績には数えません。作成日: 2026-10-01。

## この会社・職種で意識したい経験

この職種を想定するなら、**結果が思いどおりに出なかったとき、原因の仮説を自分で立てる → 条件を変えて確かめ直す → 分かったことと分からなかったことを分ける → 人に説明して反応を受け取る**経験が話しやすいです。公式採用サイトの求める人材像は「自らの想像力と創造力を発揮できる人」で、「論理的に物事を考える力」「視野の広さと柔軟な思考能力」「何事にも主体的に取り組む力」を挙げ、選考には研究内容のプレゼンテーションがあります。

## 修正前のガクチカ

> 情報系の研究室で、音声認識モデルの再現実験がうまくいかなかったことに力を入れて取り組みました。卒業研究で先行論文のモデルを自分で実装したところ、論文に書かれた精度より10ポイント近く低い結果しか出ませんでした。最初はコードの間違いを疑って何度も見直しましたが、見つかりませんでした。そこで学習データの前処理、学習率、乱数の初期値の三つを疑い、一つずつ条件を変えて精度を記録しました。すると前処理で無音区間を切る方法が論文と違っていたことが分かり、直すと精度の差は三ポイントまで縮まりました。残りの三ポイントは乱数の初期値を五回変えても縮まらず、原因は特定できませんでした。研究室の進捗報告で、縮まった理由と縮まらなかった部分を分けて説明したところ、先生から残りの差は論文側の報告方法の問題かもしれないという指摘をもらい、次の実験の方針が決まりました。うまくいかないときに疑う場所を決めて一つずつ試すこと、分からないことを分からないと言って人に見せることの大切さを学びました。

## 何を改善したか

修正前でも粘り強さは伝わりますが、本人がどこで何を判断したのかが作業の列挙に埋もれていました。改善版では、コードの見直しをやめて三つの条件に疑いを絞った判断、前処理の違いを突き止めた確かめ方、縮まらなかった三ポイントを「分からない」と分けて報告した判断を中心にしました。先生の指摘で次の方針が決まった流れも残し、説明した相手の反応まで書いています。

## 改善版ガクチカ

> 情報系の研究室で、音声認識モデルの再現実験の差を突き止めることに取り組みました。先行論文のモデルを実装すると精度が論文より10ポイント低く、コードを見直しても原因が見つかりませんでした。そこで疑う場所を前処理・学習率・乱数初期値の3つに絞り、1つずつ条件を変えて精度を記録しました。無音区間の切り方が論文と違うと分かり、直すと差は3ポイントまで縮まりました。残りは初期値を5回変えても縮まらず、原因は特定できませんでした。進捗報告では縮まった理由と縮まらなかった部分を分けて説明し、先生から論文側の報告方法の可能性を指摘され、次の実験方針が決まりました。うまくいかないときは疑う場所を自分で絞って1つずつ確かめ、分からない部分を分けて人に見せることが、研究を前に進めるうえで重要だと学びました。

## この例の強いところ

長時間がんばった話ではなく、疑う場所を3つに絞った判断と、1つずつ条件を変えて確かめた手順を書いています。全部を解決したと言い切らず、縮まらなかった3ポイントを分けて報告し、説明した相手の指摘が次の方針につながった流れまで残しています。

## これから経験を作るなら：課題設定10例

| 課題 | おすすめする理由 |
| --- | --- |
| 先行研究の再現実験をやり直す | 結果の差から仮説を立てて確かめる経験ができる |
| 実験装置の測定誤差を減らす | 疑う場所を絞って1つずつ試す練習になる |
| プログラムの処理時間を短くする | 原因の切り分けと前後比較を数字で示せる |
| センサーのデータの欠けを調べる | 分からない部分を分けて報告する練習になる |
| 統計解析の前処理を標準化する | 条件の違いが結果を変えることを確かめられる |
| 学会発表の説明を作り直す | 専門外の相手に5分で説明する経験ができる |
| 研究室の共有コードを整理する | 他人が再現できる形にする意識が育つ |
| 自作のアプリを友人に使ってもらう | 想定と違う使われ方から次の改善を決められる |
| 競技プログラミングの解法を比べる | 考え方の違いを論理的に説明できる |
| 他分野の論文を読んで自分の研究に応用する | 視野の広さと柔軟な思考を示せる |

## 進め方

結果が合わないとき、最初に「疑う場所」を3つ程度に絞り、1つずつ条件を変えて記録します。全部を見直すより、何を疑わなかったかも含めて書いておくと、面接で判断の理由を説明できます。

分かったことと分からなかったことは、報告のときに必ず分けます。分からなかった部分に対して相手から受け取った指摘と、それで決まった次の方針を残しておくと、人に見せて前に進めた経験として話せます。
