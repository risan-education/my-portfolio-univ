# 任天堂を想定したガクチカ例

想定職種: **制作企画系**

企業研究: [令和就活ラボ・任天堂](https://risan.jpn.org/?p=14165) ／ 基本例: [IT・情報通信](../01-it.md)

## この会社・職種で意識したい経験

制作企画系を想定するなら、**作る → 第三者に遊んでもらう → どこで止まったか観察する → 面白さの設計を変える → 締切から修正範囲を選ぶ**経験が話しやすいです。作品の完成度だけでなく、遊ぶ人の反応から何を変えたかを示します。

## 修正前のガクチカ

> ゲーム制作サークルで、大学祭の謎解き企画を試遊で直して仕上げることに力を入れました。企画担当として仕掛けを考えましたが、3週間前の試遊では最初の謎が難しく、半数が途中でやめました。私は難易度を下げるだけでなく、どこで止まったかを記録し、最初の謎を解ける手応えを出す役割に変える方針にしました。謎を3段階に並べ替え、全部は間に合わないため最初の2つを優先しました。試遊を計3回行い、当日は完走する人が増えましたが、序盤が簡単すぎたという感想もありました。

## 何を改善したか

修正前にも試遊と改善がありますが、「難しいから簡単にした」という話にも読めました。改善版では、どこで止まり、どこで面白さを感じるかを観察し、**最初の謎の役割そのものを考え直した**ことを中心にしました。また、締切までに全部を直せないため、最初の2問と導線を優先した判断を明示しています。

## 改善版ガクチカ

> ゲーム制作サークルで、大学祭の謎解き企画を試遊から作り直しました。開催3週間前の試遊で参加者の半数が最初の謎で離脱しました。私は単に難易度を下げるのではなく、「どこで止まり、どこで面白いと感じるか」を記録し、最初の謎の役割を考え直しました。序盤は解ける手応えを作り、その後に難しくなる3段階構成へ変更しました。締切上すべては直せないため、最初の2問と導線を優先し、担当者と分担しました。3回の試遊で停止地点を更新し、本番では完走者が増えました。一方「序盤が簡単すぎる」という声も残りました。この経験から、作り手の意図より遊ぶ人の反応を観察し、締切の中で直す場所を選ぶことを学びました。

## この例の強いところ

「ゲームを作った」という制作経験ではなく、遊ぶ人の反応から設計を変えています。試遊を3回繰り返し、時間制約の中で優先順位を決め、改善後にも残った不満を記録しているため、企画・制作の判断を具体的に話せます。

## これから経験を作るなら：課題設定10例

| 課題 | おすすめする理由 |
| --- | --- |
| ゲームを試作して試遊する | 作り手と遊び手の認識差を観察できる |
| 謎解き企画を改善する | 停止地点を記録して難易度を調整できる |
| ボードゲームを制作する | ルール変更を繰り返し検証できる |
| 動画の離脱点を分析する | 視聴者が離れる瞬間を数字で確認できる |
| 子ども向け遊びを試作する | 年齢による理解の違いを観察できる |
| UIの操作テストをする | 説明なしで使えるかを検証できる |
| イベント演出を改善する | 観客の反応と運営制約を両方考えられる |
| 物語の読者テストをする | 意図した感情が伝わるか確認できる |
| カードゲームのルールを調整する | バランスを反復テストできる |
| 展示の体験導線を改善する | 来場者がどこで止まるか観察できる |

## 進め方

完成してから見せるのではなく、粗い段階で第三者に試してもらいます。「面白かった？」だけでなく、どこで止まったか、説明を求めたか、迷ったかを記録します。

すべての指摘を直すのではなく、期限と影響範囲から優先順位を決めます。修正後も否定的な感想を残し、「次なら何を変えるか」まで記録します。

## 面接で深掘りしたい質問

1. なぜ単純に難易度を下げるだけでは不十分だと思ったのですか。
2. 最初の謎にはどんな役割が必要だと考えましたか。
3. なぜ最初の2問と導線を優先したのですか。
4. 「簡単すぎる」という感想をどう評価しますか。
5. もう1週間あれば、何をどの順番で直しますか。
