# JR東日本を想定したガクチカ例

想定職種: **総合職（鉄道の現場・企画）**

基本例: [鉄道・交通インフラ](../08-infrastructure.md)

## この会社・職種で意識したい経験

この職種を想定するなら、**危険を見つける → 確認方法を仕組みにする → 守られない理由を聞く → 手順を簡素化する → 異常時の判断基準を事前共有する**経験が話しやすいです。

## 修正前のガクチカ

> ワンダーフォーゲル部の安全係として、装備点検を続けることと、天候悪化時の判断に力を入れました。春の山行で雨具の不足が出発後に分かり、口頭だった点検を点検表に変え、前日と当日の二回、部員が記入して私が確認する形にしました。慣れた部員ほど記入が雑になったため、理由を聞いて重要な項目だけに絞りました。夏合宿三日目の朝に天候が悪化した際は、気象情報と部員の疲労を見て、山頂を目指す行程を短縮する案をリーダーに提案し、決まった変更内容と理由を全員に説明しました。山頂に行きたかった部員から不満が出ましたが、理由を繰り返し伝え、下山後に改めて意見を聞きました。合宿は全員無事に終えましたが、判断基準が事前になかったことが不満の原因だと分かり、天候と体調で行程を変える基準を先に共有する仕組みを提案し、次の合宿から使われました。点検を続けることと、異常時の判断基準を先に共有することを学びました。

## 何を改善したか

修正前は装備点検と行程変更という二つの出来事が並んでいました。改善版では両方を、**安全を個人の注意力に頼らず、守れる手順と判断基準に変える**という一本のテーマでつなぎます。点検表を作って終わらず、記入が雑になった理由を聞いて項目を絞った点、行程変更後の不満から事前共有の不足に気づいた点を強調します。

## 改善版ガクチカ

> ワンダーフォーゲル部の安全係として、装備点検と天候悪化時の判断方法を改善しました。春の山行で雨具不足が出発後に判明したため、口頭確認を前日・当日の点検表に変えました。しかし慣れた部員ほど記入が雑になったため、理由を聞き、項目を安全上重要なものに絞りました。夏合宿では天候悪化と部員の疲労を確認し、山頂を目指さず行程を短縮する案をリーダーに提案しました。不満も出ましたが判断材料を全員に説明し、全員無事に終了しました。振り返ると不満の一因は変更基準を事前共有していなかったことでした。次回から天候・体調による変更基準を出発前に共有しました。安全は確認作業だけでなく、守れる手順と判断基準を作ることだと学びました。

## この例の強いところ

「安全第一」と言うだけでなく、点検表が守られなかった失敗まで扱っています。異常時には安全側へ判断し、その判断への不満も振り返って、次回は変更基準を事前共有するところまで仕組みにしています。

## これから経験を作るなら：課題設定10例

| 課題 | おすすめする理由 |
| --- | --- |
| 合宿の装備点検を改善する | 安全確認を継続可能な手順にできる |
| イベント安全チェックを作る | 複数人で確認する仕組みを経験できる |
| 自転車点検制度を作る | 日常的な安全管理を記録できる |
| 防災訓練を改善する | 異常時の役割と判断を考えられる |
| 混雑時の誘導を改善する | 安全と利用者利便を両立して考えられる |
| 登山計画の中止基準を作る | 続行・中止の判断基準を明文化できる |
| 実験室の安全確認を改善する | 専門的なリスクを手順に落とせる |
| サークル車両管理を改善する | 点検・記録・引継ぎを経験できる |
| 避難経路を検証する | 通常時と非常時の違いを考えられる |
| 夜間イベントの安全対策を作る | 視認性・人員・連絡方法を検討できる |

## 進め方

安全対策では「事故が起きなかった」を成果にしすぎず、ヒヤリハットや手順が守られなかった場面を記録します。作ったルールが使われない場合は、守らない人を責める前に、項目数・時間・理解度を確認します。

中止や変更を伴う活動では、当日だけでなく事前に判断基準を共有します。変更後に出た不満も記録し、安全と納得の両方を改善します。
