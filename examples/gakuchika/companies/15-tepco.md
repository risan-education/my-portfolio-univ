# 東京電力を想定したガクチカ例

想定職種: **技術系**

企業研究: [令和就活ラボ・東京電力](https://risan.jpn.org/?p=14554) ／ 基本例: [鉄道・交通インフラ](../08-infrastructure.md)

## この会社・職種で意識したい経験

この職種を想定するなら、**安全上の制約を把握する → 事前申告でリスクを減らす → 要望を数字で説明する → 安全を崩さない代替案を作る → 当日の抜けを次回へ反映する**経験が話しやすいです。

## 修正前のガクチカ

> 大学祭実行委員の設備班で、模擬店の電源容量の管理に力を入れました。前年は当日に分電盤の遮断で複数の店が止まったと聞き、各店に使用機器と消費電力を申告してもらう様式を作り、区画ごとの上限と申告の締切を実行委員会で決めて配りました。締切後に追加の調理機器を使いたいという苦情が出ましたが、上限と申告済みの合計を数字で示して断り、代わりに使用時間帯を分ける案を出して、隣の店と時間をずらす調整を他の班と行いました。融通が利かないと言われても、決まりの理由を繰り返し説明しました。当日は容量超過による遮断は起きませんでしたが、巡回で申告と違う機器を使う店が二件見つかり、その場で使用を止めてもらいました。申告漏れと時間帯分散の結果を報告書にまとめ、次年度は当日の確認を最初から計画に入れる提案を残しました。決まりを守る側に立つと苦情は避けられないこと、数字と代替案を添えると説明が通ることを学びました。

## 何を改善したか

修正前では「ルールを守らせた」という印象が強く、本人の判断がやや見えにくい文章でした。改善版では、追加機器を単に断るのではなく、**安全上変えられない容量上限を数字で示したうえで、使用時間をずらす代替案を作ったこと**を中心にしました。当日には申告外機器が見つかったため、事前申告だけでは不十分だと考え、次年度の巡回へ改善しています。

## 改善版ガクチカ

> 大学祭実行委員の設備班で、模擬店の電源容量を管理しました。前年に容量超過で複数店舗が停止したため、各店の使用機器と消費電力を事前申告する仕組みを作りました。締切後に追加機器を使いたいという要望が出ましたが、私は区画上限と申告済み合計を示し、安全上そのまま追加できないと説明しました。一方で営業を止めない方法として、隣店と使用時間をずらす案を他班と調整しました。当日は遮断を防げましたが、申告外機器を使う店が2件見つかりました。そこで次年度は当日巡回を最初から計画に入れる案を残しました。安全上変えられない条件を守りながら、数字と代替案で相手と調整することを学びました。

## この例の強いところ

安全と利用者要望が衝突する場面で、ルールを機械的に適用するだけでなく、変えられない条件と変えられる条件を分けています。事前対策で終わらず、当日に見つかった抜けを次年度の運用改善につなげています。

## これから経験を作るなら：課題設定10例

| 課題 | おすすめする理由 |
| --- | --- |
| 大学祭の電源容量を管理する | 安全上の上限と利用者要望を調整できる |
| イベント設備を点検する | 事前確認と当日確認の違いを経験できる |
| 延長コードの安全管理を改善する | 身近な電気リスクを手順化できる |
| 消費電力を測定する | 数字を基に改善案を作れる |
| 節電企画を行う | 利用者行動と設備条件を両方考えられる |
| 設備予約を改善する | 限られた設備を公平に配分できる |
| 防災設備を確認する | 非常時に必要な条件を整理できる |
| 実験機器の管理を改善する | 安全・利用・点検を仕組みにできる |
| 充電設備の運用を考える | 需要と容量制約を扱える |
| 非常時の手順を作る | 平常時と異常時の判断を設計できる |

## 進め方

まず安全上絶対に超えられない条件を確認し、数字で説明できるようにします。そのうえで利用者の目的を聞き、時間、場所、機器など変えられる条件から代替案を探します。

事前申告だけで安心せず、当日の実態を確認します。ルール違反があれば「誰が悪い」で終わらせず、なぜ事前の仕組みで防げなかったかを振り返ります。

## 面接で深掘りしたい質問

1. なぜ事前申告が必要だと考えたのですか。
2. 追加機器を認められない理由をどう説明しましたか。
3. 使用時間をずらす案はどのように考えましたか。
4. 申告外機器が出た原因をどう考えますか。
5. 次年度は事前申告と当日確認をどう組み合わせますか。
