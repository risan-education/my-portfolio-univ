# コンサルティングのガクチカ例

想定職種: **業務改善の支援**

## この業種・職種で意識したい経験

この職種を想定するなら、**最初の原因仮説を置く → 当事者へ聞く → 仮説が違えば捨てる → 問題を工程へ分ける → 改善後の残課題も確認する**経験が話しやすいです。

## 修正前のガクチカ

> ゼミの発表準備で、資料の提出方法を見直しました。8人の班で進行係を担当した際、提出が遅れて読み合わせの時間が取れず、練習できる状態を作りたいと考えました。初めは締切の周知不足を疑いましたが、班員に聞くと、必要な完成度が分からず相談を待っている人がいました。そこで、完成品を一度に集める方法から、構成案を先に共有して途中で相談する方法への変更を提案しました。班員と確認日を決め、共有用の見本も作りました。次の発表では全員が読み合わせ前に構成案を共有し、論点を相談できました。ただし、最終資料の遅れは残りました。この経験から、最初の仮説を押し通さず、相手の事情を聞いて改善案を作り、残る課題も確かめる姿勢を学びました。

## 何を改善したか

修正前でも聞き取りはありますが、提出遅れを「締切の周知不足」と考えた本人の仮説が外れたことが弱めでした。改善版では、班員への聞き取りから「完成度が分からず相談を待っている」という別の原因を発見し、締切強化ではなく途中共有へ仕組みを変えた判断を中心にしました。

## 改善版ガクチカ

> ゼミの8人班で、発表資料の提出遅れを改善しました。進行係だった私は当初、締切の周知不足が原因だと考えました。しかし班員に聞くと、「どの完成度で途中相談してよいか分からない」ため作業を止めている人がいました。そこで締切を強く伝えるのではなく、完成品を一度に集める方式をやめ、構成案を先に共有して途中確認する方法を提案しました。見本と確認日も作り、次の発表では全員が読み合わせ前に構成案を共有できました。一方、最終資料の遅れは残りました。最初の仮説を押し通すのではなく、当事者に聞いて原因を分け、改善後にも残った問題を確認することを学びました。

## この例の強いところ

解決策から入らず、最初の仮説が外れたことを認めています。改善後も最終資料の遅れが残ったため、問題を完全解決した成功談ではなく、次の分析へつながる経験です。

## これから経験を作るなら：課題設定10例

| 課題 | おすすめする理由 |
| --- | --- |
| 提出遅れを分析する | 人ではなく工程に原因を探せる |
| アンケート回収を改善する | 複数仮説を比較しやすい |
| 学食混雑を分析する | 時間帯・導線・人員を分けて考えられる |
| イベント参加率を分析する | 認知・申込・参加へ分解できる |
| 会費未納を改善する | 周知・方法・期限の原因を分けられる |
| ゼミ進行を改善する | チームの作業工程を観察できる |
| 待ち時間を分析する | ボトルネックを特定できる |
| SNS反応を分析する | 内容・時間・対象を比較できる |
| 業務手順を改善する | 現状工程と理想工程を比較できる |
| 地域集客を改善する | 来場までの段階を構造化できる |

## 進め方

問題を見つけてもすぐ施策を決めず、原因候補を3つ程度書きます。当事者へ聞き、観察・数字と合わせて有力な原因を絞ります。改善後にも同じ指標を確認し、残った問題を次の仮説として残します。

## 面接で深掘りしたい質問

1. なぜ最初は締切周知が原因だと思ったのですか。
2. 班員への聞き取りで何が変わりましたか。
3. なぜ途中共有を選んだのですか。
4. 最終資料の遅れが残った原因をどう考えますか。
5. 次にどの工程を改善しますか。
