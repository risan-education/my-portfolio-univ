# ガクチカの作り方：経験を、自分の判断と行動が伝わる文章へ

この教材の主目的は、大学新卒の就職活動で使う「ガクチカ」を、本人の経験に基づいて作ることです。テーマ未定なら[テーマの決め方](choosing-gakuchika-theme.md)、完成形を見たいなら[10業種の架空例](../examples/gakuchika/README.md)から始めます。

調査確認日: 2026-09-27。[参照資料と確認範囲](gakuchika-sources.md)。以下の手順・配分・用紙は教材としての提案です。企業共通の評価基準や、通過を保証する型ではありません。

## ガクチカとは

「学生時代に力を入れたこと」を、取り組んだ理由、課題、行動、学びとともに説明するものです。マイナビの用語解説も、経験の名称だけでなく、その過程から人柄や物事への取り組み方を伝える説明をしています。[マイナビ・ガクチカ](https://job.mynavi.jp/conts/2027/shukatsu_word/yogo_05_03.html)

| 問われること | 回答の中心 | 同じ経験を使うとき |
| --- | --- | --- |
| ガクチカ | 何に、なぜ、どう取り組んだか | 一つの経験の判断・行動・変化を詳しくする |
| 自己PR | 自分の強みは何か、何を根拠に言えるか | 強みを先に置き、経験を根拠として選ぶ |
| 志望動機 | なぜその企業・職種を選ぶか | 仕事の調査と現在の希望につなぐ。経験だけで終えない |
| 学業・研究内容 | 何を学び、どんな問いや方法を扱ったか | 専門外の相手にも対象・方法・本人の担当を説明する |

実際の設問が複数の内容を同時に聞く場合は、その設問を優先します。「ガクチカ」という名称がなくても、過去の選択や行動を聞かれる場合があります。

## 採用側の資料から分かること

ソニーの採用担当者への2022年の取材では、華やかな経験そのものより、本人が何を考えて取り組み、何を学んだかを知りたいという説明があります。肩書がない人や支える役割でも、判断と行動を伝える材料になります。これは当時の一社の説明であり、現在の全企業の採点基準ではありません。[リクルート・ソニー採用担当者インタビュー](https://shushokumirai.recruit.co.jp/column/20220216001/)

またトヨタの2025年12月の取材では、2027年卒採用に向けて、大学の一つの経験だけでなくライフラインチャートで過去の選択も理解する方向が紹介されています。特定の400字だけを暗記するより、自分の選択の経緯を説明できる準備が役立つ、と本教材では考えます。この例から「全社がガクチカを廃止した」とは言えません。[リクルート・トヨタ採用担当者インタビュー](https://shushokumirai.recruit.co.jp/column/20251224001/)

企業別の公開資料から得られる着眼点と、実際のES設問・AI利用条件は別です。募集要項・応募画面で自分の年度と職種の条件を確認します。

## 最初に確認する応募条件

[構成・確認用紙](../templates/gakuchika.md)へ、分かる範囲だけ記録します。

- 応募する法人名、業種、職種、募集年度。
- 設問の原文、字数、数え方、締切、対象期間。「大学入学以降」なら高校時代は対象外。
- AI利用条件は許可／条件付き／禁止／未確認のどれか。出典URLまたは本人用の案内控え、確認日、許される操作。
- 今回使ってよい原記録と版、本人・関係者の情報の利用範囲、最新の利用停止情報。

未確認・禁止なら、AIで提出本文を生成しません。本人用の事実整理や、提出文と切り離した教材の学習はできます。条件付きなら、例えば校正だけを認める場合に本文生成まで広げません。見つからないルールを「禁止と書いていないので許可」と判断しません。

## 6つの材料を取り出す

| 材料 | 確認したいこと | 曖昧なときの扱い |
| --- | --- | --- |
| 取り組み・期間・役割 | いつ、どの活動で、本人は何を担当したか | 日付・役割を推測しない |
| 動機と目標 | 当時、なぜ取り組み、何を目指したか | 現在の就職希望を当時の動機にしない |
| 状況と課題 | どんな問題を、何から認識したか | 事実と本人の仮説を分ける |
| 判断・行動・試行錯誤 | 何を選び、誰と調整し、どう変えたか | 「頑張った」を具体的な場面へ戻す |
| 結果と限界 | 実際にどうなり、何は分からないか | 目標値を実績値にしない |
| 学び・その後 | 考えがどう変わったか、次に何をしたか | 実施済みと今後の計画を分ける |

元メモは[活動記録](../templates/experience.md)や[プロジェクト用紙](../templates/project.md)へ残し、整理や文章案は `derived/` へ別保存します。ファイルがない経験は、回想だと明記して本人に聞きます。日付不明なら未確認のまま始められます。原記録に日付欄を後付けして書き換える必要はありません。

## 400字以内へまとめる一例

この配分は書き始めるための目安です。実際の上限と設問に合わせて変えます。STAR（状況・課題・行動・結果）のような整理法も使えますが、当時の動機や役割、学びが落ちないようにします。

| 順序 | 内容 | 仮の配分 |
| --- | --- | --- |
| 1 | 取り組みの結論、期間・役割 | 50字 |
| 2 | 動機、目標、課題 | 80字 |
| 3 | 本人の判断・具体的な行動・見直し | 170字 |
| 4 | 確認できた結果と必要な限界 | 60字 |
| 5 | 学び | 40字 |

合計400字の目安です。全部を限界まで埋める必要はなく、本教材の例は約300字です。職種との接点を聞かれていなければ、無理に「御社で貢献します」と締めず、経験の説明に字数を使います。

1. まず6つの材料を箇条書きにし、未確認を残す。
2. 「自分が判断を変えた場面」を一つ選び、行動を具体化する。
3. 許可された範囲で文章案を作り、各文の根拠を原記録に対応させる。
4. 重複する背景・抽象語を削る。結果の意味が変わる条件や本人の役割は削りすぎない。
5. 字数を測り、設問に答えているか、口頭で説明できるかを本人が確かめる。

## 抽象的な表現を具体化する

以下も架空の比較例です。[ゼミの進行改善の材料](../examples/gakuchika/06-consulting.md#架空の材料)だけを使っています。

| 曖昧な表現 | 材料に戻した表現 | 分かること |
| --- | --- | --- |
| リーダーシップを発揮した | 進行係として、構成案を先に共有する方法を提案した | 実際の役割と行動 |
| コミュニケーションを大切にした | 班員に聞き、必要な完成度が分からないという困りごとを知った | 聞いた内容と判断への影響 |
| 課題を解決した | 全員の構成案は集まったが、最終資料の遅れは残った | 改善と未解決の区別 |
| チームの成果を上げた | 班で論点を相談できた。本人は確認日と共有用の見本を整えた | 集団の結果と本人の寄与 |

「頑張った」「学んだ」を使ってはいけないのではありません。その言葉を支える場面が必要です。数字がなければ、改訂した資料、手順の違い、許可を得て記録した反応などで説明できます。後から人数・改善率・発言を作りません。

## 業種ごとにどう変えるか

[業種別10例](../examples/gakuchika/README.md)は、IT、メーカー、金融、商社、小売、コンサルティング、広告、交通インフラ、教育、医療・福祉・介護を扱います。業種名だけでテーマを決めず、職種の仕事と自分が実際に判断した場面を照合します。

例えば接客アルバイトの経験でも、相手の困りごとの把握、正確な引き継ぎ、チームでの調整という異なる面を説明できます。応募先を変えても期間・役割・成果は固定します。同じ経験のコピーや別社向け文章を別々の実績として数えません。

## よくある迷い

**目立つ実績がない。** 授業、家事、生活上の工夫、一人で続けた制作も候補です。規模より、本人が考えて動いた場面を探します。無理に受賞や役職を探す必要はありません。

**失敗したことでもよいか。** 設問が成功体験を指定していなければ候補になります。責任転嫁せず、どこを確かめ、何を変え、何が残ったかを説明します。失敗が自動的に高評価になるわけではありません。

**チーム活動しかない。** 全体の目標と本人の担当を分けます。他の人の作業を自分の成果にしません。逆に、役職がなくても行った調整や支援を具体化できます。

**数字がなく、後から思い出した。** 回想と明記し、覚えている範囲と確認できる資料を分けます。客の感想を要約で覚えている場合、正確な直接発言としてかぎ括弧で再現しません。

**高校の探究を使いたい。** 対象期間に合うか確認します。大学で続けた場合は高校と大学の期間・担当・結果を分けます。中高生版から移したからといって大学での新実績にはなりません。[移行手順](migration.md)

**今から就活向けの活動を始めたい。** 今ある関心・負担・許可範囲から小さく試せます。ただし計画を実施済みの成果にしません。選考直前に無理な役職や高額な活動を選ぶ必要はありません。[これからのテーマ選び](choosing-gakuchika-theme.md#これから取り組むテーマを決める)

## 面接と保存まで

完成文から「なぜ」「本人がしたこと」「別案」「うまくいかなかった点」「結果の根拠」を一つずつ聞きます。準備した回答を暗唱するより、文章を離れて経緯を説明できるか確かめます。分からない数字や理由は補作しません。[面接用紙](../templates/interview.md)を使い、想定問答と実際の面接記録は分けます。

本人が確認した案は `derived/applications/応募先/YYMMDD-gakuchika-v1.md` などへ保存。提出時は提出本文と提出日を固定し、後日の改善は別版へ残します。ChatGPTに書込手段がなければ、保存予定の相対パス・本文・未確認事項・保存待ちを返してもらい、[保存と再読込](saving.md)を行います。
