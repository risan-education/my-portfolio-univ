## 1. 総評

**結論: 3つの目的に対して土台は十分に適切です。特に「事実とAI提案の分離」「創作禁止」「AI利用条件の確認」「利用停止・移行」といった安全設計は、同種の公開教材の中でも突出して丁寧です。** 一方で、(1) 教材と本人記録の置き場が1つのテンプレートに同居しているため、学生の非公開リポジトリに143ファイル・約400KBの教材と架空記録が丸ごと複製される構造、(2) 目的(C)の「社会人以降のコンテキスト」が要件上は第二目的・将来拡張と位置づけられ、実装が薄い点、(3) 初めての大学1年生にとって導線が重い点、の3つが主な改善余地です。

## 3. 目的別の適合度

### (A) 公開配布元として

**良い点**
- CC BY 4.0・著作権表示・第三者資料の扱いがREADME/LICENSE/保守ガイド/要件書で一致し、検査でも表示を確認している。
- Issue/PRに実記録を送らないルール、配布元と本人用Privateの区別が繰り返し明示されている。
- 「Use this template」とZIPの2経路、ブラウザだけで完了する手順、100ファイル/25MiBの上限まで書かれている。

**課題**
1. **テンプレートに教材が同梱される。** 学生が作るPrivateには docs/ 27本、examples/ 60本超、要件定義書、scripts/、CIワークフローまで複製される。要件書・保守ガイド・受入確認は学生には不要で、ChatGPTを接続したときに検索対象を汚す。
2. **架空記録が本物と同じ形式で複製される。** `examples/journey/experiences/240415-class.md` は見出しに「（架空例）」がある以外、本人記録と同じ構造。接続したAIが検索で拾えば、教材自身が何度も警告している「架空例を実績に混ぜる」事故が起きうる。CHATGPT.mdの禁止文だけで防ぐのは弱い。
3. **教材更新の配布経路がない。** 学生のコピーは分岐した時点で固定される。migration.md の「同じリポジトリを使い続ける場合」に差分確認の手順はあるが、タグ・リリース・CHANGELOGとの対応がなく、どの版から始めたか学生側で判別できない。
4. **配布元への誤コミットを自動で止める仕組みがない。** `experiences/` 等にREADME以外が置かれてもcheck-docsは失敗しない。Issue/PRテンプレートもない。
5. GitHubのAbout（説明・Topics・記事URL）が未設定で、言語表示がPowerShellになっている。

### (B) ChatGPT接続とガクチカ対策

**良い点**
- CHATGPT.md を「明示的に渡す」設計にし、AGENTS.md自動読込をCodex限定と正しく区別している。
- 読取・ファイル作成・書込・再読込を分けた保存状態表（saving.md）は、接続型AIの典型的な失敗（「保存しました」と言うが保存されていない）を正面から扱っている。
- ガクチカは意味・自己PRとの違い・6つの材料・400字配分・抽象語の具体化・面接・保存まで一続きで、10業種の架空例は字数と表示の一致を自動検査している。
- AI利用条件「許可／条件付き／禁止／未確認」の確認を提出本文生成の前に置いている点は、2026年時点の就活実務に合っている。

**課題**
1. **ChatGPT側の具体的な接続手順が抽象的。** chatgpt-environment.md は「連携（プラグイン等）の有無を確認する」と述べるにとどまり、GitHubプラグインで実際に何ができるか（読取のみか、PR経由の書込か、対象リポジトリの絞り方）の画面例がない。学生が最初に詰まるのはここ。
2. **CHATGPT.md の長さがChatGPT側の入力上限に収まるか未確認。** 約1,700字。プロジェクト指示欄・カスタム指示欄の文字数上限は変わるため、600字程度の短縮版を用意し、長い版はプロジェクトのファイルとして渡す二段構えが安全。
3. **READMEの導線が重い。** 最初の1件に到達する前に表が2つ、リンクが20本以上ある。大学1年生の「今日の一言を残す」だけの用途に対し、就活・比較・生活費・法令が同じ画面に並ぶ。
4. **`practice/` が存在しない。** getting-started の練習手順の保存先なので、`practice/README.md` を同梱すれば初回の迷いが減る。
5. **Claude Code向けの CLAUDE.md がない。** docs/claude-code.md は学生に「CLAUDE.mdから@AGENTS.mdを参照する方法がある」と説明するが、1行のCLAUDE.mdをテンプレートに含めれば手作業が不要になる。

### (C) 社会人以降のAIコンテキスト

**良い点**
- 「原記録／現在の自己理解／用途別コンテキスト」の三層と、profile/current.md に本人確認日・見直し日を持たせる設計は、長期の「AIに自分を理解させる外部記憶」に適している。
- 「特定のAIの記憶機能に依存しない」「Markdownで持ち出せる」という要件(C-06)は、ツールが変わっても資産が残る設計として正しい。

**課題**
1. **実装が薄い。** docs/ai.md は約1,000字、docs/after-university.md は約370字。templates/ai-context.md は欄の一覧のみで、「どのAIのどこに、どの長さで貼るか」の運用がない。
2. **就職後の記録用紙がない。** 要件書は職務経歴・転職・起業を「初版の対象外」としている。学生時代の `experiences/` をそのまま使えるが、勤務先の機密・守秘義務・就業規則との関係を扱う用紙・ガイドがないと、社会人になった時点で使い方が途切れる。
3. **記事の中核主張との接続が弱い。** 記事は「生成AI時代の自分の外部記憶」を最大の価値としているが、READMEではこれが「第二目的」として末尾近くに1行あるだけ。大学生の動機付けとしては、就活と同じ強さで前面に出してよい。
4. **常設のコンテキスト（current版）がない。** 用紙は `derived/ai-context/YYMMDD-purpose.md` の目的別のみ。汎用の `derived/ai-context/current.md`（見直し日付き）を1本持ち、ChatGPTプロジェクト・Claudeプロジェクト・Copilot指示に同じ本文を貼る運用にすると、記事の主張がそのまま実現できる。

## 5. 推奨する着手順

1. H-3、H-4、H-5、M-4、M-6、L-2 は既存構造を変えずに完了できる。1回の更新（0.4.1）で対応可能。
2. M-1、M-2、M-3、C-1、C-2、C-4 はドキュメント追加・READMEの再構成。0.5.0として要件書§1・§6・§8と受入確認を同時に更新する。
3. H-1（教材とテンプレートの分離）は構成変更なので、記事の更新（M-5）と合わせて計画する。分離しない判断なら H-2 を必ず実施する。
4. C-3（就職後の用紙）は要件書の「初版対象外」を改める判断が先。本人確認日・機密の扱いを含めて最小構成から始める。

## 6. 検証の範囲と限界

- ローカルでのcheck-docs実行、独立したリンク検査、GitHub APIでの設定確認、公式URLの実在確認までを行った。
- ChatGPTの実アカウントでのプラグイン接続・書込・文字数上限、Copilot・Claude Codeでの実操作は本評価でも未検証。教材が「未検証」と明記している方針と同じ扱い。
- 就活の実務（各社のAI利用条件、選考基準）は評価対象外。教材が「企業共通の基準ではない」と述べている点は妥当。
