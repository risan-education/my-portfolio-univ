# AIで作った記録を保存する

[Copilot](copilot.md)・[Claude Code](claude-code.md)でも、以下の保存・再読込の区別を使います。ローカルのファイル編集と、コミット・pushによるGitHubへの反映は別です。

本教材では、本人用の非公開保存先にあるMarkdownを長く残す記録とします。ChatGPTの会話や出力ファイルと、本人用リポジトリの内容は分けて管理します。

## 添付・コピーで使う場合（基本の経路）

1. 今回使う資料と用紙だけをChatGPTへ渡します。本文を貼る場合は、元の相対パスと資料の種類も添えます。
2. 保存予定の相対パス、Markdown本文、未確認事項を出してもらいます。出力本文へ用紙の使い方や依頼文を混ぜないようにします。
3. 自分の言葉・日付・役割・結果を確認します。
4. ダウンロード可能な.mdがある場合は受け取り、本人用フォルダの予定パスへ保存します。ファイル出力が使えなければ本文をコピーし、UTF-8の.mdファイルへ保存します。
5. 保存先でファイルを開き直します。GitHubで管理する場合は本人用Privateへ反映し、対象ブランチ上でも再表示します。
6. 次の相談で必要なら、保存した現在版を添付し直します。チャット側の古い添付を現在版と混同しません。

ChatGPTが生成したファイルの保存先は、本人用の保存先とは限りません。[公式のファイル利用案内](https://learn.chatgpt.com/docs/artifacts-viewer)を参照してください。

## 保存先へ直接書ける場合

利用中の環境で実際に使える書き込み手段があり、本人が対象を指定した場合に利用します。

> 本人用の［保存先］の［相対パス］へ、確認した本文を保存してください。同名があれば上書きせず別名にし、保存後に読み直してください。保存先、変更ファイル、版、再読込結果を報告してください。

GitHubの読取ができるだけでは書き込み可能とは限りません。[環境の確認](chatgpt-environment.md)で使える操作を区別します。書き込みできなければコピー方式へ切り替えます。新しいプラグインを無条件に追加する必要はありません。

## 保存状況の伝え方

| 状態 | 何ができたか | 次にすること |
| --- | --- | --- |
| 案を表示・保存待ち | チャットに本文がある | 本文を確認し、本人用保存先へ保存 |
| ファイル作成・反映待ち | ダウンロード用ファイルがある | 受け取り、本人用保存先へ反映 |
| 保存済み・再読込未確認 | 保存操作が終わった | 保存した本文を読み直す |
| 保存済み・再読込確認済み | 保存先の実ファイルを確認した | 次回はこの版を参照 |

書き込み操作の失敗時は保存済みにしません。コピー方式では本人が開き直したという報告と、ChatGPT自身が読み直せた事実も区別します。
保存先の実行権限がなく、同名の存在も調べられない場合は「保存予定」とし、本人が衝突を確認します。

## 既存の記録と提出控え

原記録の当時の考えは保持し、現在の解釈は日付付きの振り返りへ。提出済みの本文と日付は固定し、修正案は別版へ置きます。既存の旧記録を用紙に合わせて書き換えません。
外部資料の原本、チャットの添付、本人用の控えの所在は[資料の所在](../templates/asset.md)で区別します。
