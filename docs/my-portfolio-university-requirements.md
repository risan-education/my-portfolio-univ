## 1. 目的と設計方針

小学生版・中高生版から継続でき、大学生が就職活動にもAIへのコンテキスト提供にも使えるポートフォリオ教材を配布する。

2026-09-26〜27の追加指示を反映し、大学新卒の就活でのガクチカ作成を主目的とする。次の優先順位で案内する。

| 区分 | 目的・方針 |
| --- | --- |
| 第一目的 | 大学新卒の就職活動におけるガクチカの作成。本人の経験・学び・判断を蓄積し、根拠付きで伝える。自己分析、仕事選び、他の応募書類、面接にも活用する |
| 利用の中心 | 大学1年から使う記録。普段の大学生活で経験し、振り返り、次の行動を考えるところから始める |
| 第二目的 | 就活のために蓄積したポートフォリオを再利用し、AI用のコンテキストも作れるようにする |
| 将来の活用 | 就職後の心構え、転職対策、起業のヒントとしても継続利用できるようにする |

追加要件として、自己分析でBig Fiveのどの特性が高く出そうか、得意なこと、苦手なこと、好きなこと、嫌いなことを、参考程度に出力する仕組みを含める。本人を確定的に分類する用途ではなく、自己理解と就活準備に使う。

さらに「企業を見極め、自分を守り、納得して選ぶ」支援を含める。企業・職場の比較、働くルール、内定後の意思決定、相談先を優先し、生活費の見通しと本人が選んで共有する保護者との相談メモも用意する。就職先を本人が判断するための教材として、大学1年のアルバイトから使えるようにする。

コンセプトは、**大学1年から経験と考察を積み重ね、就活で自分の選択と行動を根拠付きで伝えられるポートフォリオ**とする。就活直前に過去の経験を振り返って始めることもできる。

以下を教材の設計方針とする。READMEでは最初にガクチカ作成への使い道を示し、日常の記録から自己分析・企業研究・ES・面接へ進む道筋を案内する。AIコンテキストは蓄積した情報から作り、専用の記録を毎回追加する負担を生じさせない。就活用に文章を整える際も、元の事実と当時の考えを保持する。

Markdownの用紙・架空の記入例・ガイド・AI編集指示を配布する。実記録は本人用の非公開リポジトリまたは非公開フォルダに保存する。ChatGPTとの対話を標準の入口とし、GitHub Copilotも選べる。慣れている人向けにClaude Codeの利用も案内する。モデル・有料プラン・APIキー・独自アプリを固定要件にしない。直接保存できない環境では本人がMarkdownを手動保存する。

### 1.1 AIとの対話・初期設定・保存

- ChatGPTはアカウント登録・任意の有料契約・本人用Privateの準備から[開始手順](getting-started.md)を案内する。GitHub Copilotは学生認証・特典有効化・VS Codeへのログイン・保存までを[専用ガイド](copilot.md)に含める。無料特典の対象と利用上限は公式情報・確認日とともに示す。
- [Claude Code](claude-code.md)は慣れている人向けの選択肢とし、その利用条件を他サービスの契約や学生特典と混同しない。
- 用紙はAIへ渡す出力形式として使い、本人は一言・資料・訂正を伝える。全項目の記入を要求せず、必要な質問を少数ずつ行う。
- 通常のChatGPTにはCHATGPT.mdを明示的に渡す。指示欄の文字数が足りない場合はCHATGPT-short.mdを渡し、全文は資料として添える。本人用GitHubへの接続は[接続手順](chatgpt-github.md)で読取・書込・再読込を区別して確認する。編集環境ではAGENTS.mdを共通ルールとし、Copilot用の入口は.github/copilot-instructions.mdに置く。利用ツールの指示探索や設定を確認し、自動読込を一律に仮定しない。
- 出力は保存予定の相対パス・Markdown本文・未確認事項・保存状況を区別する。用紙の依頼文や案内は記録本文へ混ぜない。
- 読取・ファイル作成・本人用保存先への書込・再読込を区別する。書込手段がなければ本文を返し保存待ちとする。チャット表示や生成ファイルをリポジトリへの保存完了としない。
- ローカル保存・コミット・push・対象ブランチでの再表示を区別する。最初にpractice/以下の架空記録で保存・追記・再読込を練習する。
- 次の会話では共通指示・目的・今回使う資料の現在版と最新の停止情報を確認する。古い添付を現在版とみなさない。共有プロジェクトや接続範囲は本人が確認する。
- 各サービスの申請・契約・UIの実操作、実データ移行を検証したかは、文書・架空例の検査とは分けて受入確認に記載する。

## 3. 利用者と利用場面

- 主な利用者: 文系・理系を問わない大学生本人。GitHubやMarkdownに詳しいことを前提にしない。
- 支援者: 本人が選ぶキャリア相談員、教員、先輩、家族など。共有は本人が選んだ資料に限る。
- 配布元: 教材を保守する。学生の実記録を収集・評価する運用は設けない。
- 継続利用: 過去の記録がなくても始められ、卒業後も持ち出せる。就職後の心構え・転職・起業のヒントへの再利用を見据える。0.5.0から職務経験の記録用紙を最小構成で提供する。職務経歴書・事業計画書・入社後の専用教材は対象外のまま。

次の入口は、第一目的である就活対策へつながる日常の使い方と、第二目的のAI活用を示す。

| 入口 | できること | 主な成果物 |
| --- | --- | --- |
| 残す | 授業、ゼミ、研究、アルバイト、サークル、趣味、生活の経験を記録する | 一言メモ、活動記録、作品カード |
| 深める | 課題を調べ、方法を選び、試行錯誤と協働を記録する | 探究・研究・プロジェクトの記録 |
| 振り返る | 関心・価値観・得意なことの候補を根拠と照らして考える | 振り返り、現在のプロフィール |
| 就活に使う | 経験と企業・職種への理解をつなぎ、応募・面接と就職先の選択に使う | 経験の棚卸し、企業研究、ES下書き、面接準備、職場比較、内定後の意思決定 |
| 働く準備をする | 働くルール、相談先、生活の見通しを確認する | 労働法の学習メモ、相談先カード、生活費の見通し、保護者との相談メモ |
| AIに伝える（第二目的） | 既に蓄積した記録から、今の相談に必要な背景・判断基準・経験を選んで渡す | 短い自己紹介、目的別コンテキスト |

### 大学1年から就活までの利用例

| 時期の目安 | 主に取り組むこと | 就活へのつながり |
| --- | --- | --- |
| 大学1年から | 授業、アルバイト、サークルなどで、行動・理由・工夫・気づきを短く残す | 後から具体的に説明できる経験を蓄積する |
| 経験が増えてきたとき | 複数の記録を振り返り、関心や強みの候補、伸ばしたい点、次に試すことを考える | 自己分析と仕事選びの軸を育てる |
| インターン・企業研究を始めるとき | 仕事内容への理解と自分の経験・希望を照らし合わせる | 志望理由の材料と、確かめたいことを整理する |
| 応募・面接のとき | 設問や職種に合わせて記録を選び、自分の役割・判断・学びを説明する | ESと面接で一貫した事実を伝える |

時期は利用例であり、固定の就活日程や学年ごとの必修課程ではない。日々の記録で志望企業や自己PR文の入力を要求しない。本人が経験を振り返って次の行動を選べることも支援し、成果だけでなく試行錯誤を残す。

## 4. 記録の要件

| ID | 初版で提供する要件 |
| --- | --- |
| R-01 | 一言メモから始められる。入力頻度、最低文字数、全項目の記入を要求しない。 |
| R-02 | 活動記録に、活動時期、背景、取り組んだ理由、課題、自分の役割、判断と工夫、結果、学び、次の行動を任意で記録できる。 |
| R-03 | 本人の元メモ、事実、本人の考察、直接発言、要約、代筆・支援者の観察、他者からの評価、AIの提案を区別する。要約を直接引用に変えない。日付・数値が不明なら未確認とする。 |
| R-04 | 集団の成果と本人の貢献、計画と実施、期待した効果と実際の結果を分ける。数値のない成果、失敗、中断、迷いも残せる。 |
| R-05 | 研究・制作には、問い、方法、根拠、変更理由、成果物、限界を残せる。専門分野ごとの公式研究記録の代替とはしない。 |
| R-06 | 中高生版の6段階の探究設計を任意で継続できる。大学の研究や全活動に、その順序や全段階を強制しない。 |
| R-07 | 作品・発表・資格・スキルは、具体的に何をしたかと確認できる資料を結びつける。受講、知識、自力での実践を区別する。 |
| R-08 | AIを活動で使った場合、任せた部分、本人が判断・検証した部分、分かった限界を任意で残せる。 |
| R-09 | 当時の考えを保ち、現在の振り返りは日付付きで別に書く。訂正・追記は日付と理由を残す。 |
| R-10 | 活動日・記録日・ファイルの作成日・更新日を区別する。後日思い出して書いた記録は回想と分かるようにする。 |

普段の用紙は短くし、詳しい質問は任意の補助に回す。例えばアルバイトの引き継ぎを工夫した経験は、日々の記録、協働の振り返り、ガクチカ、AIへの判断例として再利用できる。同じ事実を用途ごとに原記録へ重複入力しない。

### 4.1 中高生版と共通にする記録形式

| ID | 共通仕様1.0への対応 |
| --- | --- |
| F-01 | 本文はUTF-8のMarkdownとし、特定のAI・独自形式・アプリ・データベースを必須にしない。 |
| F-02 | 新しい活動記録のファイル名は原則 `YYMMDD-theme.md`（例: `260927-seminar.md`）。活動日不明は `date-unknown-theme.md`、同名がある場合は `-02` 等を付ける。既存ファイルを上書きしない。 |
| F-03 | 新しい記録の本文では活動日・記録日・作成日・更新日を分け、`YYYY-MM-DD` で記載する。不明は「未確認」。固定の入口・索引などは役割に応じた名前とし、一律に日付付きへ改名しない。 |
| F-04 | 旧記録の名前・配置・本文・日付・状態・代筆や観察の記載を保持する。日付欄の追加、改名、大学生版の用紙への転記を強制しない。旧形式のファイル名も受け入れる。 |
| F-05 | YAMLや一律の記録IDを本人に入力させない。タグと索引は任意で、なくても検索・記録・移行ができる。 |
| F-06 | 要約・報告は `derived/` に原記録と別に保存し、主張ごとに根拠を示す。長期の自己紹介の現在版は `profile/` に置き、本人確認日を付ける。 |

新規記録の形式チェックと旧記録の保持確認は分ける。日付欄がない旧記録をエラーとして書き換えない。時期が不明な記録を就活に使う場合は未確認として扱い、提出設問の対象期間に含まれるかを別途確かめる。

## 5. 就職活動の要件

以下の用紙とガイドを提供する。利用者は必要なものだけ選ぶ。

| ID | 要件 | 記録する内容 |
| --- | --- | --- |
| J-01 | 経験の棚卸し | 取り組み、本人の役割、行動、成果、学び、根拠へのリンク。授業や日常の改善も対象にする |
| J-02 | 自己分析 | 大切にしたいこと、働く条件、得意・苦手・好き・嫌いの候補、Big Fiveで高く出そうな特性の参考整理。根拠・反例・未確認事項・本人の確認日を付ける |
| J-03 | 業界・企業・職種研究 | 法人名、対象職種・募集年度、事業・仕事内容、確認できた情報、出典URL・確認日、本人の感想、未確認事項 |
| J-04 | 応募先との接点整理 | 関心を持った理由、関連する経験、仕事で取り組みたいこと、今後学ぶこと。会社の事実と本人の希望を分ける |
| J-05 | ES等の下書き | 応募先・設問・文字数・対象期間・AI利用条件と、回答に使う原記録を対応させる。自己PR・ガクチカ・志望動機を扱う |
| J-06 | 面接準備・振り返り | 根拠に沿った説明、想定される深掘り質問、不足する確認事項、実際に受けた質問、次回の改善 |
| J-07 | 応募状況の簡易管理 | 企業・職種、締切と出典、選考段階、提出した版、次の行動へのリンク。日程の自動取得・通知は初版に含めない |
| J-08 | 企業・職場の比較 | 働く時間・休み、定着・育成、仕事内容・配属、給与・勤務地、両立支援を、本人の希望と照合する |
| J-09 | 働くルールの基礎 | アルバイト・インターン・就職に関する短い事例から、労働条件と公的資料を確認する |
| J-10 | 内定後の意思決定 | 大切にしたい条件、確認済み・未確認の情報、気になる点、選択理由を整理する |
| J-11 | 生活費の見通し | 額面と手取りの見込み、家賃・生活費・奨学金返済等を条件付きで比較する |
| J-12 | 相談先の準備 | 大学・公的機関等の窓口と、相談したい事実・質問を整理する |
| J-13 | 保護者との相談 | 本人が選んだ進路・理由・迷い・希望する支援を1枚に整理する |

ESは「下書き・本人確認済み・提出済み」を区別し、応募先と設問ごとに保存する。提出済みの本文と提出日は固定して残し、改善案は別の版にする。同じ経験を別の企業に使う際も、役割・期間・数値の事実が変わらないよう確認する。

中高生版からの経験を含め、エピソード一覧には原記録へのリンクを付け、本人の役割・選択・行動・結果・学びを区別する。設問の対象期間に合う記録を選び、元記録・移行コピー・要約を重複した活動として数えない。応募先ごとの企業・職種・年度・設問・字数・AI条件を管理し、提出控えと実際の面接記録を別に保存する。

提出先のAI利用条件は「許可・条件付き・禁止・未確認」と出典を記録する。未確認を許可とは扱わず、提出本文の作成に先立って確認する。確認中も、自分用の経験の整理は進められる。

応募条件、給与、勤務地、配属、選考方法などは年度・職種で異なるため、各社の採用ページと説明会で確かめる必要がある。テンプレートに特定年度の就活日程や企業条件を固定しない。

### 5.1 参考としての自己分析レポート

初版では、本人が選んだ記録をAIが読み、追加の質問と本人の確認を経て、自己分析レポートを出力する。用紙・AIへの依頼文・出力ルール・架空例で実現し、独自アプリを必須にしない。用紙はChatGPT・Copilot等への出力依頼として使い、本人が事実を確認する。

| 出力 | 整理する内容 |
| --- | --- |
| 得意なことの候補 | うまくできた行動、工夫、他者の評価、再現できた条件 |
| 苦手なことの候補 | つまずく場面、負担を感じる作業、必要な支援、改善を試した結果 |
| 好きなことの候補 | 本人が楽しい・続けたいと述べた活動、惹かれるテーマや環境 |
| 嫌いなことの候補 | 本人が避けたい・消耗すると述べた活動や環境と、その条件 |
| Big Fiveの傾向 | 開放性、誠実性、外向性、協調性、神経症傾向の5特性について、記録に表れている傾向と不明な点 |
| 就活での活用案 | 自己PRに使えそうな経験、働きやすい条件の仮説、企業研究で確かめたい点、次に試す行動 |

得意と好き、苦手と嫌いは別々に扱う。「得意だが好きではない」「好きだがまだ苦手」も表せる。記録が多いことだけで好きと判断せず、実施経験がないことを苦手と判断しない。単発の失敗を恒常的な弱点にせず、場面や慣れの影響も確認する。

### 5.2 Big Fiveの表示方法

記録からの推測では、各特性を「高めに出そうな手がかりがある／低めに出そうな手がかりがある／場面によって異なる／材料不足」で整理する。これは本教材の参考表示であり、質問紙の測定値や同年代集団との比較ではない。「場面によって異なる」を平均値、「材料不足」を低得点として扱わない。

特に高めに出そうな特性の候補を示せるが、5特性の得点順位や最も高い特性を無理に決めない。根拠が足りない場合は、その旨と確認したい質問を返す。記録だけから「外向性82点」「上位10%」などの測定値や確率を作らない。神経症傾向と情緒安定性は得点の方向が逆になるため、表記と方向を明示し、混同しない。

実際の数値を表示する機能は、本人が回答した質問紙を所定の方法で採点する別方式として検討する。採用する尺度・日本語版の根拠・利用条件・逆転項目・欠損回答の扱い・得点範囲を確認してから実装する。集団内の高低や百分位は、適切な比較データがある場合のみ表示する。AIの推測と質問紙の結果は別欄に保存し、一致させるための改変や平均化をしない。現行教材では質問紙採点を実装せず、将来の拡張として別途検討する。

### 5.3 出力と本人確認の要件

| ID | 要件 |
| --- | --- |
| S-01 | 対象期間・対象記録・作成日・分析方法を明示し、各候補に具体的な原記録へのリンクを付ける。 |
| S-02 | 候補ごとに、支持する経験、当てはまらない経験、成立する場面、不明な点を分ける。自己申告と実際の行動・他者評価も区別する。 |
| S-03 | Big Fiveは5特性すべてを一覧にし、未推定の項目も明示する。高低を優劣・道徳性・知能・採用可能性の点数に置き換えない。 |
| S-04 | 記録には就活用に選ばれた経験などの偏りがあることを踏まえ、本人全体の性格として断定しない。人格・精神疾患の診断には使わない。 |
| S-05 | 追加質問は不足する情報に絞り、本人は回答を省略できる。望ましい性格や成功談に合わせる誘導をしない。 |
| S-06 | 本人が「しっくりくる／一部違う／違う／保留」を選び、修正理由を残せる。AI案と本人確認後の内容を区別する。 |
| S-07 | レポートは日付付きで `derived/self-analysis/` に保存する。現在の自己分析への採用は本人が選び、過去のレポートと原記録を上書きしない。 |
| S-08 | 職種との相性は、仕事の具体的な条件と経験を照らして検討する候補として示す。Big Fiveだけで向いている職業・向いていない職業を確定しない。 |
| S-09 | ESでは具体的な行動と学びを使う。性格の推測や苦手・嫌いの一覧を、応募書類やAIコンテキストへ自動転記しない。 |

出力例の形式は「候補 → 根拠 → 反例・条件 → 本人の確認 → 就活への活用案」とする。例えば架空例では「得意：資料を整理して説明する／好き：少人数で疑問を掘り下げる」を別々に示し、外向性は材料不足のままでも完了できる。

参照資料（2026-09-26確認）: [IPIPの得点解釈](https://www.ipip.ori.org/InterpretingIndividualIPIPScaleScores.htm)は、得点の高低を比較集団との関係で扱い、特性を連続的に捉える説明をしている。[IPIP Big-Five Factor Markersの採点キー](https://ipip.ori.org/newBigFive5broadKey.htm)は、特性別の項目と正・逆方向を示し、第4因子を情緒安定性としている。これらは質問紙の扱いの参考であり、ポートフォリオからのAI推測の妥当性を保証する資料ではない。

### 5.4 企業・職場の比較（ホワイト企業を調べる入口）

会社を調べる際は、次の比較項目を用意する。既存の企業研究から参照し、同じ情報を二重入力しない。

| 観点 | 確認する内容 |
| --- | --- |
| 働く時間・休み | 残業、有給取得、休日、繁忙期、集計対象と期間 |
| 定着・育成 | 新卒採用者数・離職者数、研修、相談・指導体制 |
| 仕事内容 | 応募職種、配属の決め方、実際に任される仕事、異動 |
| 給与・生活 | 基本給、固定残業代、住宅支援、勤務地・転勤 |
| 続けやすさ | 育児・介護との両立、相談窓口、制度と利用実績 |

- 各項目に出典URLまたは資料の所在、対象年度、確認日、対象法人・職種・部署を記録する。全社平均と応募先部署の実態は区別する。
- 数値を比較する際は、対象者・期間・単位を確認する。離職率だけでなく採用者数・離職者数も確認し、異なる集計条件を同じものとして比較しない。
- 求人票・公的情報・説明会での回答・口コミ・本人の感想を区別する。情報がない場合は「未確認」とし、0や問題なしと置き換えない。
- くるみん・えるぼし・ユースエール等は、認定名、対象分野、対象法人、確認日を記録する。認定の有無だけで会社全体を安全・危険と判定しない。
- 本人の「必須・希望・許容できる・まだ決めていない」という条件と照合できるようにする。ホワイト度の総合点や企業の自動ランキングは作らない。
- 未確認の項目から説明会・面談で聞く質問を作り、回答と出典を追記できるようにする。

### 5.5 大学1年から学ぶ働くルール

労働基準法を含む労働法の基礎を「短い事例 → 自分の状況と書面を確認 → 最新の公的資料 → 必要なら相談」の流れで扱う。

- 給与明細、求人票、労働条件の書面を読む。基本給・固定残業代の金額と時間数・超過分の扱いを分けて確認する。
- 労働時間、休憩、休日、有給、賃金・残業代、退職、ハラスメント、労働保険・社会保険の基礎を必要な場面から学べるようにする。
- アルバイトやインターンでの疑問も扱う。インターンは名称だけで法令の適用を決めず、契約と実際の活動内容を確認する。
- 学習メモには、事例、自分が疑問に思った点、確認した資料・確認日、分かったこと、未確認事項、次の相談先を残す。法律の暗記や全項目の修了を要求しない。
- 法令・制度の説明には公式資料、適用条件、確認日を付け、制作・改訂時に現行情報を確認する。改正前の説明と現在の説明を混在させない。
- AIは事実整理と確認先の案内を支援する。限られた記録から個別事案の違法・合法を断定する仕組みにはしない。

### 5.6 内定後の意思決定

内定先を選ぶシートには、本人が大切にしたいこと、確認できた労働条件、未確認事項、納得して受け入れる点、気になる点、最終的な選択理由と日付を残す。1社だけでも使え、保留して追加確認する選択もできる。

求人時の説明と提示された労働条件を照合し、相違点は確認事項として残す。確認済みの情報と本人の期待を分け、企業比較・自己分析・生活費の見通しを参照する。Big Fiveは判断の補助とし、その傾向だけで職種や会社を選ばせない。自動の内定承諾・辞退は行わない。

### 5.7 初任給と生活費の見通し

額面給与、手取りの見込み、家賃、食費、光熱・通信、通勤、奨学金返済、その他の支出、一時的な引っ越し費用などを任意で整理する。勤務地や実家暮らし・一人暮らしの条件を変えて比較できる用紙にする。

初版は本人が調べた金額を記入する簡易な収支表とし、税・社会保険の自動計算は必須にしない。概算には対象年、居住地や扶養等の前提、出典、確認日を付ける。実額・概算・未確認を区別し、未確認を0円にしない。賞与等の不確実な収入を確定収入に混ぜず、計算可能な部分の残額と未確認の費目を示す。初年度と翌年度で条件が変わる場合も区別する。

### 5.8 困ったときの相談先カード

大学のキャリアセンター・学生相談室、公的な労働相談窓口などから、本人が使える窓口をまとめる。相談内容、対象者、連絡方法、受付時間、公式URL、最終確認日を持たせ、利用時に最新情報を確認する。

相談準備用紙には「いつ・どこで・何があったか」「関連する書面や記録の所在」「何を確認したいか」「希望する支援」を記載する。事実と本人の受け止めを分け、相談内容や証拠資料を保護者・企業・AIに自動共有しない。機微な相談記録は本人が選んだ非公開の保管先で管理する。記入の完成を待たずに相談できる案内にする。

### 5.9 本人が選んで見せる保護者との相談メモ

本人が共有する範囲を選び、次の内容を1枚にまとめる。

- 今考えている進路と、その理由。
- 企業について確認できたこと。
- まだ迷っていること。
- 手伝ってほしいこと。
- 今は自分で進めたいこと。

共有相手・共有する内容・本人の確認日を記録する。親の希望と本人の希望を区別し、親の希望で本人のプロフィールや意思決定を上書きしない。Big Fiveの推測、苦手・嫌いの一覧、日々の個人的な記録は自動で含めない。保護者との共有は任意で、共有しなくても全機能を利用できる。本人が希望すれば別の支援者との相談にも使える。

## 6. AIコンテキストの要件

AI用コンテキストの作成は第二目的とし、初版では既存の記録と自己分析から短い自己紹介・目的別文書を作る範囲を基本とする。AIを使って記録や就活準備を支援することと、蓄積した記録をAI用コンテキストとして再利用することは区別する。機能を選ぶ際は、大学1年からの記録の続けやすさと就活への活用を優先する。

### 6.1 元記録から用途別の情報を作る

情報は次の三層で扱う。

1. **原記録**: 実際の経験、本人の言葉、判断、作品。長期保存の土台。
2. **現在の自己理解**: 今の関心、目標、価値観、希望する支援方法。本人が確認して更新する。
3. **用途別コンテキスト**: 今回の相談に必要な情報だけを選んだ持ち出し用の文書。

| ID | 初版で提供する要件 |
| --- | --- |
| C-01 | 短い基本プロフィールと、就活相談・研究相談・学習計画などの目的別コンテキストを作れる。 |
| C-02 | 今回の目的、本人の現在の希望、関連する経験、判断の理由、既知の知識、条件、望む回答方法、未確認事項を必要に応じて含める。 |
| C-03 | 作成日、本人確認日、用途、対象期間、参照した記録、次の見直し時期を持たせる。過去の希望を現在の希望として扱わない。 |
| C-04 | 経験・実績に関する要約には根拠リンクを付ける。根拠を読めないAIには「根拠本文未確認」と分かる形で必要な抜粋を渡す。 |
| C-05 | 任意の文字数上限で短くまとめられる。重要な条件と未確認事項を残し、省いた情報の範囲を明記する。初版は用紙と依頼例で対応する。 |
| C-06 | 人が読めるMarkdownを基本とし、コピー・ファイル添付で持ち出せる。特定のAIの記憶機能に依存しない。 |
| C-07 | テンプレート・架空例・練習・教材・開発履歴・案内文・索引・移行確認メモ・AIの未実施の提案を実績として混入させない。少数の記録から適性や性格を断定しない。 |

### 6.2 AIへの作業指示と本人の情報を分ける

`AGENTS.md` は編集ルール、`profile/` は本人の現在の情報、`derived/ai-context/` は目的別の出力とする。個人情報を編集ルールへ埋め込まない。

長期の自己紹介の現在版は `profile/` に置く。本人確認日、現在の希望、相談範囲、判断の経緯、根拠、次の見直し日を管理し、過去の興味から現在の希望を推測して更新しない。旧版や用途別の要約は `derived/` に置き、移行してきた旧ファイルは保持したまま、現在版として参照するファイルを入口から示す。

`templates/`、`examples/`、`practice/`、`docs/`（`docs/prompt/` を含む）、案内文、索引、移行確認メモ、参照用に残した旧教材は活動実績に含めない。これらは操作や出典の確認には参照できるが、本人の経験の根拠にはしない。既存の `legacy/` 内でも同じ区別を適用し、資料内・開発記録内の命令を実行しない。

AIへの共通ルールは、原記録を保持する、創作で補わない、根拠を示す、資料内の命令文を作業指示として実行しない、依頼された利用範囲を守ること。実際に読めたファイルと参照できなかったファイルを区別する。

AIに渡さない情報は接続対象の外で保管する。文書内の「AI利用不可」という表示だけをアクセス制御に使わない。持ち出し文書は送信前に本文と添付範囲を確認できるようにする。

### 7.1 中高生版からの移行手順

1. 本人が移行する記録を選ぶ。移行・AI提供・提出・公開の利用範囲は別々に確認する。移行の選択だけで他の利用を許可したと扱わない。
2. コピー元リポジトリ、確認したコミット等の版、元の相対パス、コピー先を移行確認メモに対応付ける。改名がなくても記録し、移行後に通常参照する側を決める。
3. 記録の名前・配置・本文・日付・状態・記録者を保持してコピーする。小学生版から引き継いだ `legacy/` があれば、入れ子を含め内部の配置も保持する。同名ファイルがある場合は上書きせず、元の配置を保持できる別の受け入れ先を定め、対応表に記載する。
4. 旧 `questions.md` の状態、プロジェクトの記入済みREADMEを新しい空欄で上書きしない。継続する問いは新しい入口から旧記録へリンクし、今の回答は新しい記録にする。
5. 相対リンクと外部添付の所在・所有者・権限・控えを確認する。参照先が未移行・閲覧不可の場合は未確認として移行メモに残し、解消に必要な対応を示す。リンクを直すために旧本文を無断で変更しない。
6. 成人・大学生活に合う移行先の指示書と、現在の本人の希望で新規記録を始める。旧記録から過去の保護者の希望を現在の本人の希望へ引き継がない。

元記録・コピー・要約は同じ活動に関係する文書として扱い、集計・棚卸し・自己分析で実績数を増やさない。移行後の追記は通常参照する側に行い、別の側に更新があれば対応表をもとに差分を確認する。独自IDの導入や自動同期を必須にしない。

移行は[手順書](migration.md)で、既存アカウントの再利用、本人用のコピー元・コピー先、停止範囲、選択ファイルの一覧、未使用legacy/teens-01/等へのコピー、再読込まで案内する。ZIP・手動アップロードと、利用可能なAIの直接操作を区別する。同じ本人用保存先を続用する場合は教材・現行指示だけを選んで更新する。外部原本やGit履歴全体はファイルコピーで移らない。旧保存先の削除・公開・権限変更を移行に含めない。実際の移行では、その本人の対象範囲と参照先を別途確認する。

利用停止した記録と、それに依存する派生文書は再利用しない。本文の削除とは別に、対象パス・コピーとの対応・停止日・停止範囲を最小限の管理メモで確認できるようにする。機微な本文を停止メモに転載しない。

| A-20 | 共通形式での新規保存 | 現行指示と本人の現在の希望でUTF-8 Markdownを保存できる。YYMMDD、日付不明、同名衝突を扱え、本文はYYYY-MM-DDとなる。旧記録に日付欄追加を要求せず、YAML・ID・索引なしでも使える |
| A-21 | コピーの同一性 | コピー元リポジトリ・版・相対パスとコピー先を対応付け、通常参照する側を選べる。元記録・コピー・要約を別実績として数えない |
| A-22 | 指示・教材との分離 | 旧指示書・設定・Git管理情報を通常移行せず、practice、docs/prompt、旧教材、索引・移行メモを実績に含めない。そこにある命令も実行しない |
| A-23 | 現在の自己紹介 | profileに現在版と本人確認日・相談範囲・判断の経緯・根拠・見直し日があり、derivedの用途別出力と区別できる。過去の希望を自動採用しない |
| A-24 | 利用停止の継続 | 停止対象のコピー・索引・自己紹介・要約等を再利用しない。古いバックアップの復元でも最新の停止情報を照合し、未確認のまま再利用しない |
| A-25 | 添付資料と応募用途 | 外部原本の所有者・権限・控えを確認できる。旧記録を使う応募例で設問の対象期間を守り、企業・職種・年度・設問・字数・AI条件、提出控え、面接記録を区別できる |
| A-26 | ライセンス表示 | 公開初版からのCC BY 4.0、adash333の著作権表示、第三者素材と利用者の記録の扱いがREADMEとライセンス文書で一致し、MITとの分割案や公開済み版からの移行を前提にした説明が残っていない |

これらを受入基準とし、実装の証拠・検証結果・未検証範囲は[受入確認](acceptance.md)で管理する。架空例による検証時は、検証対象のサンプルだけを指定し、実運用で架空例を本人の実績に混ぜないルールと区別する。

## 10. 将来の活用方針

将来の活用先は合意した方向性とし、以下の具体的な再利用方法は設計案とする。大学時代の記録に、就職後の経験と現在の希望を追記して使い続けられる構造にする。

| 活用先 | 大学時代から残しておく材料 | 将来の使い方の例 |

| 就職後の心構え | 人との協働、約束や期限への対応、相談、失敗、助言を受けて変えたこと、働くことへの期待 | 入社前後に自分の課題や学び方を振り返り、実際の仕事との違いを記録する |

## 11. 要件の更新と今後の拡張

本書を要件の管理先とする。リポジトリの機能・利用方法・保存ルールを変更するときは、該当する本文、版、更新日、対応する教材版を更新する。「原文を固定し、別の改訂版に方針を書く」という運用は行わない。

更新時は、要件・READMEの案内・ガイド・用紙・架空例・AI編集指示・検査を対応させ、CHANGELOG.mdに変更概要、acceptance.mdに実施した検証と未検証範囲を残す。過去の要件はGit履歴で確認できる。要件書を更新可能にしても、本人の原記録、提出済み本文、架空移行の同一性の保持は継続する。

| 拡張の論点 | 現行の扱い |
| --- | --- |
| 応募管理の詳細化 | 簡易なMarkdown管理。自動応募・通知は含めない |
| Big Fiveの質問紙採点 | 記録からの参考傾向だけを扱う。採点は尺度と検証を含む別の拡張 |
| 就職後・転職・起業の専用教材 | 継続保存と再利用を案内。専用教材は将来の拡張 |
| AIサービスの追加・変更 | 共通の記録形式とルールを保ち、公式情報と実際の利用環境を確認してガイドを更新 |
