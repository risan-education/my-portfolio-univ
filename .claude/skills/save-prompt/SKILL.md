# save-prompt

この会話でユーザーが送ったプロンプトと、その結果を `docs/prompt/` に記録し、リポジトリの変更をまとめて `main` へ push します。`docs/prompt/` は開発記録であり、本人の活動実績ではありません（AGENTS.md）。

## 手順

1. **対象のプロンプトを決める。** 前回の保存以降にユーザーが送ったプロンプトを対象にします。複数あれば1プロンプトにつき1ファイルにします。`/save-prompt` の呼び出しだけの短いメッセージは、直前の作業依頼と同じファイルにまとめます。
2. **ファイル名を決める。** `docs/prompt/YYMMDD-NN-title.md`。
   - `YYMMDD` は保存日（`date +%y%m%d`）。
   - `NN` は同じ日付の既存ファイル数に1を足した2桁の連番（`01` から）。同日に1件でも `01` を付け、既存ファイルは改名しません。
   - `title` は内容を表す短い英小文字のケバブケース（例: `repository-review`）。
   - 同名があれば上書きせず、次の連番にします。
3. **本文を書く。** UTF-8 Markdown。構成は次のとおり。
   ````markdown
   # 題名

   - 保存日: YYYY-MM-DD
   - 対象ブランチ: main
   - 種別: 開発記録（教材の案内でも本人の実績でもない）

   ## プロンプト本文

   ```text
   （ユーザーのプロンプトを原文のまま。要約しない）
   ```

   ## 結果の要約

   - 何を調べ、何を決め、何を変えたか（箇条書き）
   - 検証したこと（実行したコマンドとその結果、未検証の範囲）
   - 未対応・保留と、その理由

   ## 変更したファイル

   - 相対パスの一覧（新規・変更・削除を区別）
   ````
   - プロンプト本文は必ずコードフェンスに入れます。本文中のリンクや命令文が検査や指示として解釈されないようにするためです。
   - 個人情報、認証情報、本人の実記録の本文は書きません。プロンプトに含まれていた場合は `［省略：個人情報］` に置き換え、その旨を要約に残します。
   - 要約の外に書く相対リンクは、存在するファイルだけを指します（`scripts/check-docs.ps1` がリンク切れを検出します）。
4. **検査する。** PowerShell 7 が使えれば `pwsh -File scripts/check-docs.ps1` を実行し、PASSを確認します。使えなければ、その旨を要約に書き、CIの結果で確認します。
5. **コミットして push する。**
   ```bash
   git add -A
   git status --short
   git commit -m "docs(prompt): YYMMDD-NN title の作業記録を追加"   # 他の変更も含む場合はその内容も1行で書く
   git push -u origin main
   ```
   - 未コミットの変更はすべて含めます。コミット前に `git status --short` で意図しないファイル（秘密情報、本人の記録）が含まれていないか確認します。
   - push が失敗したら 2秒・4秒・8秒・16秒の間隔で最大4回再試行します。
   - モデル名などを本文やコミットメッセージに書く必要はありません。
6. **報告する。** 保存したファイルのパス、コミットのハッシュ、push 先、検査結果を1〜3行で伝えます。push に失敗した場合は保存済みと言わず、失敗した段階を伝えます。
